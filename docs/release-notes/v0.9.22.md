Scroblytics now keeps its database in a file of its own, warns you instead of silently starting over if that database is ever emptied, and fixes two smaller problems: backups that couldn't be chosen when restoring, and a Metric button bar that could collapse on Overview.

## Your database has its own file
Until now the database lived in a file named `default.store` in your `Application Support` folder, a name any app on a Mac can share. A different program that opened the same file with its own layout could remove Scroblytics' tables from it. From this version the database is `~/Library/Application Support/Scroblytics/Scroblytics.store`, beside the images, so no other program touches it.
- **Nothing to do.** The first time you open this version it makes a copy of your existing database in the new place, checks the copy (its integrity and the row count of every table against the original) and only then starts using it. It takes a moment. Your history, loved tracks, saved queries, flags, playlists and everything else carry over.
- **The old file is left alone.** The copy is made from a read-only view of `default.store`, which is never changed or deleted. Once you've checked that everything looks right you can delete it. If anything goes wrong with the copy, Scroblytics keeps using the old file as before and tries again the next time it opens.
- Starting over later (deleting the new file) really starts over: the old `default.store` is not brought back.

## A clear warning if a database is emptied
Scroblytics now looks at the database file before it opens it. If the file is large but holds no listening history, it no longer quietly creates an empty database and starts importing again. It shows **Your Scroblytics database has been emptied**, explains what it found, and changes nothing.
- If you have a copy of the file from before (Time Machine, Backblaze or another backup), put it back and open the app again.
- **Start Over (Keep the File Aside)** moves the emptied file into a `Recovered Databases` folder and starts a new database, so your history imports again. Nothing is deleted, and the file can still be used to recover data later.
- After starting over, **File › Restore Backup…** brings back the things you created.
- A new, small or missing database is never flagged, and neither is one that holds a history.

## Fixed
- **Restore Backup… couldn't choose your backups.** Backup files (`.scroblyticsbackup`) appeared greyed out in the Open dialog, because the app never declared its own file type. They can be chosen now. If you are still on an earlier version and hit this, copy the backup and give the copy the ending `.json`; the app reads the contents of the file, not its name, so that should let you choose it.
- **The Metric buttons on Overview could collapse** into truncated labels ("Met…", "S…") at random, and went back to normal only after a relaunch. Overview, Top Charts, Library and Timeline now all use the app's own button bar for Scrobbles / Time Listened, which falls back to a menu in a very narrow window, and a narrow header wraps its controls instead of squeezing them. If you ever see the buttons collapse again, please report it.

## Under the hood
- Help › Where your data lives describes the new file, the one-time copy and the emptied-database screen.
- Three new automated checks cover the copy (including a database with and without log files, another program's file, a damaged file, an interrupted copy), the launch inspection of the file, and the header layout.

## Requirements and install
macOS 15 or later (Apple silicon or Intel) and a Last.fm account. Download `Scroblytics-0.9.22.dmg` below, open it and drag **Scroblytics** to **Applications**, replacing the old copy. Your data is copied to its new file the first time you open it. To verify the download, compare its SHA-256 with the attached `Scroblytics-0.9.22.dmg.sha256`.
