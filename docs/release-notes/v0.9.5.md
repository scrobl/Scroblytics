# Scroblytics 0.9.5 (beta)

A performance release for large listening histories.

## Fixed

- **Pages no longer redo all their work every time background lookups report progress.** While Scroblytics works through a long backlog of lookups (tags, track lengths, release dates), it announces progress every few seconds. Trends threw its data away and recalculated every chart each time, and a recalculation that had been replaced kept running on top of the next one. On a large history that left Trends loading with several processor cores busy. Trends, Query, Top Charts and Timeline now refresh for background progress at most every few minutes (and as soon as you open the page), and Trends runs a couple of chart calculations at a time and skips one that has been replaced.
- **The listening history is read once and shared.** Every page used to read the whole history for itself, so opening a page cost seconds of processor time and each page held its own copy in memory. The app now keeps one copy for all of them, and checks cheaply whether it is still current. Memory no longer grows as you visit more pages.
- **Overview starts faster on a bigger library.** Several things that went through the whole history again for every card or every row (trend lines, the Most Recent / Most Often list, streaks, a picture check run once per play) now do it in one pass, with the same results.

## Requirements and install

macOS 15 or later (Apple silicon or Intel) and a free Last.fm API key, as before. Download `Scroblytics-0.9.5.dmg` below, open it and drag **Scroblytics** to **Applications**, replacing the old copy. Your data stays where it is. To verify the download, compare its SHA-256 with the attached `Scroblytics-0.9.5.dmg.sha256` (`shasum -a 256 Scroblytics-0.9.5.dmg`). If you're on 0.9.3 or earlier the app will tell you about this version (a strip under the toolbar, or **Scroblytics › Check for Updates…**).
